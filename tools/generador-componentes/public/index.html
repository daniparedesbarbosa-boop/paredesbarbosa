Comprobando los patrones que existen en este proyecto...

Paso 1 de 5

¿Qué pantalla quieres crear?

El nombre técnico se usa para formar el archivo Vue. La ruta es la dirección que se abrirá en el navegador.

Paso 2 de 5

Define la entidad y sus campos

Una entidad es el tipo de dato que guardarás. Esta versión crea una colección nueva y usa el identificador automático _id de MongoDB.

Campos

Los nombres técnicos se mantienen iguales en MongoDB, JSON, API y Vue.

Los selectores y radios usan opciones fijas. Un campo de tipo catálogo carga su lista de un JSON: el generador analiza la estructura y, si los datos son nuevos, crea backend/data/<nombre>.json y el módulo de src/api/ que lo importa directamente. No hay que añadir rutas a backend/server.js ni depende de MongoDB. La subida de archivos no se genera; las relaciones con otras entidades se configuran en el paso 4.

Paso 3 de 5

Elige las operaciones

No todas las pantallas necesitan todas las operaciones. Las casillas se validan entre sí para evitar generar acciones sin utilidad y el tipo de pantalla elegido debe coincidir con la lógica que se genera.

La validación de campos configurada en el paso anterior se aplicará en el navegador y en el esquema Mongoose. El listado mostrará todos los registros e incluirá un buscador local que filtra por el texto de sus columnas.

Paso 4 de 5

Relaciones y estado compartido

Las relaciones con pacientes guardan el DNI (dnipac) como texto; las de doctores y citas guardan el ObjectId con referencia ref. Solo está disponible para entidades nuevas y pantallas CRUD, Relacionado o Formulario.

Relaciones con otras entidades

El backend comprobará con Modelo.exists() que cada documento relacionado existe antes de guardar.

El selector de la API usa la lista real del recurso (por ejemplo getPacientes de src/api/pacientes.js). El modo Pinia consume la selección compartida que establecen pantallas como XestionPacientes o XestionDoctores y, en general, cualquier entidad que tenga su store en src/store/, incluidas las generadas antes con esta herramienta; si no hay store, solo queda el selector.

Compartir la selección de esta pantalla (Pinia)

Genera src/store/<entidad>Store.js y un botón «Compartir» en la tabla, siguiendo el patrón de doctorStore.js.

Necesita la operación listar (el botón Compartir vive en la tabla) y al menos un campo definido en el paso 2.

Paso 5 de 5

Revisa antes de generar

Confirma los nombres normalizados y la carpeta de salida. No se modificarán archivos de src/ ni de backend/.

Abre un archivo configuracion.json generado anteriormente para revisarlo o regenerarlo.
